# RHL-W4-001 — Thesis, Expectation Gap & Research Lifecycle

Status: `IMPLEMENTED / SOL ACCEPTANCE PENDING`

Accepted ancestor: `1f1fef4d2db455af2ff17e9703701e1a98659eae` (`RHL-W3-001 + FIX-002`).

This Wave 4 slice promotes four bounded, independently callable Research Skills:
`thesis_formalize`, `expectation_gap`, `catalyst_map`, and `thesis_refresh`. It
also strengthens the existing `thesis_red_team` peer with categorical fragility
assessment and executable kill-criterion evaluation, and adds a Workflow-owned
CREATE/REFRESH lifecycle composition.

## Acceptance boundary

- `thesis_formalize` validates explicit propositions, evidence basis, references,
  cycles, verification conditions, and load-bearing dependencies.
- `expectation_gap` compares traceable price-implied, consensus, management, and
  own-research surfaces only when metric, period, unit, and basis are compatible.
- `catalyst_map` requires proposition linkage, observable outcomes, timing, and
  attributable sources; it does not infer directional investment conclusions.
- `thesis_refresh` requires a prior snapshot, applies point-in-time evidence,
  preserves unaffected propositions, and evaluates only sourced kill criteria.
- `thesis_red_team` remains a semantic Workflow peer and does not become a
  composite Skill or mutate canonical Knowledge.
- `thesis_lifecycle` is Workflow composition; Skills do not invoke one another.

## Architecture and governance invariants

No Knowledge Schema change, Agent Runtime, Planner, generic Capability layer,
Skill-to-Skill call, direct canonical mutation, or BUY/SELL/HOLD output is
introduced. Canonical persistence remains behind the existing Knowledge
Production Gateway and Writer boundary. Fixture/offline E2E evidence does not
claim authenticated provider or model availability.

## Runtime result

The canonical catalog target is now `21 IMPLEMENTED`, `4 PARTIAL`, and
`4 PLANNED`. The four promoted Skills have deterministic runtime bindings and
canonical SKILL.md contracts. Dispatch collision tests preserve narrow direct
routes for the four new intents and the existing red-team intent; broad
lifecycle requests remain Workflow-routed.

## E2E classification

Scenarios A-D are covered by deterministic local tests: CREATE composition,
REFRESH with targeted evidence, irrelevant evidence/no-drift preservation, and
sourced kill-criterion met. These are contract-level E2E scenarios. Authenticated
external-provider and model-backed semantic validation remain pending.

## Deferred
